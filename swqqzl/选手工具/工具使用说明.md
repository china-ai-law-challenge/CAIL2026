# 工具使用说明（选手版）

本目录是 CAIL 2026 赛题提供的**选手工具集**。所有脚本**仅依赖 Python 标准库**
（Python 3.10+），无需安装第三方包。

> **关于评分**：官方评分由平台在提交后统一执行，**不向选手分发评分脚本**。
> 评分口径的**唯一权威来源**是 `01_赛道说明文档/01_赛题说明与评分规则.md`，
> 本说明与其逐项对齐。若两者表述冲突，以赛题说明文档为准。

---

## 一、工具清单

| 脚本 / 文件 | 用途 | 读真值 | 说明 |
| --- | --- | :---: | --- |
| `check_submission.py` | **提交格式自检** | ✘ | 提交前必跑，能拦掉绝大多数格式问题 |
| `submission_sample.jsonl` | **提交格式样例（6 条）** | — | 覆盖 6 种关键形态，可直接照抄字段写法 |
| `baseline.py` | 下限基线（仅用输入侧特征） | 仅 train | 1 秒级跑完，建立分数下限 |
| `reference.py` | 纯 Python 参考解 | 仅 train | 约 30 秒 / 2,100 条，产出可自检的完整提交 |
| `stats.py` | 数据规模与分布统计 | — | 位置参数传 jsonl 路径 |
| `工具使用说明.md` | 本文件 | — | — |
| `../schema/labels.json` | **全部编码表** | — | 类型 / 要件 / 措施 / 义务 / 法条 / 锚点 |

> `baseline.py` / `reference.py` **只从训练集学习**，不会读取初赛/复赛/封测的任何信息，
> 可以放心运行与参考。它们的作用是让你先跑通流程、拿到一个分数下限，
> **不是性能上限**，更不是标准答案。

## 二、提交格式自检（最重要，提交前必跑）

```bash
cd 04_选手工具

python check_submission.py --pred my_submission.jsonl --data "../02_选手数据集/初赛_无真值/prelim.jsonl"
```

> 复赛阶段的 `--data` 换成当阶段发放的输入文件即可（本包只含初赛输入；封测阶段不发放输入）。

退出码：存在 ERROR 时为 `1`，否则为 `0`（仅 WARN 不影响退出码）。
建议在你的流水线末尾直接 `|| exit 1`，把格式问题挡在提交之前。

不读真值，逐项检查：JSON 合法性、`sample_id` 覆盖与唯一性、编码是否合法、
字段间自洽（如「不构成侵权 ⇒ `infringement_types` 为空列表」、
「`organized_infringement` 与 `organizer_liability` 不得矛盾」）、
`priority_order` 非空且与措施同集合、`citations` 非空且为真实编码等，逐项输出 ERROR / WARN。

### 关于样例文件

`submission_sample.jsonl` 是**取 6 条用于演示字段写法的片段**（取自**初赛**划分，
所以 `sample_id` 与你手上的初赛输入是一致的），**不是某个划分的完整提交**。
直接对它跑 `check_submission.py --data 初赛输入` 只会报「缺少 N 条样本预测」——**这是预期的**。
它检验的是你的完整提交，不是这份 6 条演示。

样例覆盖的 6 种关键形态（**建议逐一对照检查你的模型是否都覆盖了**）：

| # | 形态 | 看点 |
| ---: | --- | --- |
| 1 | 构成侵权 + 平台担责 + 措施满档 | 常规形态，8 项措施全给 |
| 2 | **不构成侵权 + 全部判空** | 最易踩坑：`infringement_types`、`disposal_measures`、`priority_order`、`citations` **全为空** |
| 3 | 部分构成侵权 + 合法表达豁免 | `exemptions` 非空，但措施仍要给 |
| 4 | **组织化侵权 `true`** | `organized_infringement` 与 `organizer_liability` 必须同时体现组织者责任 |
| 5 | **存疑待查 + 措施判空** | 边界为「存疑待查」时，task_C 两项措施字段**同样应为空列表**（判空计分，不是缺失） |
| 6 | 平台连带责任 | `platform_liability` 最重的一档，常伴随处置档位提升 |

## 三、跑通流程：参考解与基线

```bash
# 参考解：训练集与初赛集路径已内置，**不带 --train/--data 即可跑通**
python reference.py --out submission_reference.jsonl
python check_submission.py --pred submission_reference.jsonl --data "../02_选手数据集/初赛_无真值/prelim.jsonl"

# 下限基线：1 秒级
python baseline.py --out submission_baseline.jsonl
```

> ⚠ **这两个脚本只是「跑通流程 + 拿到下限」的工具，不是标准答案。**
> 官方参考解在初赛上的水平约为：侵权类型 Macro-F1 0.31、平台责任 F1 0.87、
> 处置措施 F1 0.75、数据溯源率 0.52 —— 说明本赛题**远未饱和**，
> 有大量可提升空间。上界（预测=真值）为全项 1.0000。

## 四、统计与编码表

```bash
python stats.py "../02_选手数据集/训练集_含真值/train.jsonl"   # 位置参数，不是 --data
python stats.py "../02_选手数据集/初赛_无真值/prelim.jsonl"
```

对无真值的划分，会自动跳过标签分布统计（这是正常的）。

`labels.json` 位于 `schema/labels.json`，是**评测与选手共用的唯一编码真相**，含：

- `infringement_types`：标签体系中的全部侵权类型（含仅在封测阶段出现的类型），每条带 `elements` 与 `law`；
- `elements`：要件编码及 `element_necessity`（必备 / 情节）；
- `element_values`：构成 / 不构成 / 不适用 / 存疑；
- `boundary_values`、`severity`、`exemptions`；
- `liability`：责任形态取值域；
- `disposal_measures`：M01—M16 + `disposal_urgency_order`（基础紧迫序）+
  `disposal_urgency_modifier`（案情档位修正，如 `爆` 档 M03 提权）；
- `law_articles`：法条编码；`case_anchors` / `type_case_anchors`：案例锚点编号；
- `ood_reserved_types`：仅会在封测阶段出现的类型编码（用于校验输出编码是否越界）。

## 五、常见报错与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `缺少 N 条样本预测` | 提交不含全部输入样本 | `sample_id` 须覆盖输入文件**全部**样本，无缺无多无重复 |
| `sample_id` 不匹配 | 误按行号对齐 | 必须按 `sample_id` 对齐；CSV/JSONL 行序不保证一致 |
| 某编码不在合法域 | 直接写了中文或自造编码 | 查 `schema/labels.json`，只能用其中的编码 |
| 边界与类型矛盾 | 「不构成侵权」却给了类型 | 不构成侵权 / 存疑待查 ⇒ `infringement_types` 必须为**空列表** |
| `organized_infringement` 与 `organizer_liability` 冲突 | 两者独立预测 | 二者**严格等价**，须由同一结论派生 |
| `priority_order` 报集合不一致 | 漏项或多项 | 必须与 `disposal_measures` **同集合非空**，且按紧迫度重排 |
| `citations` 为空 | 忘填门限项 | 逐样本给出**真正相关**的法条编码 / 案例锚点 |

## 六、评分口径要点（以赛题说明文档为准）

| 指标 | 口径 |
| --- | --- |
| 侵权类型 | 多标签 Macro-F1（逐类型后平均） |
| 构成要件 | 要件级 F1；**计分取 micro**，macro 仅作诊断输出 |
| 边界结论 | 4 类 F1 + 边界子集完全一致率 |
| 责任主体 | 发布者 + 组织者合并多标签 Macro-F1 |
| 平台义务 | 义务类型集合多标签 F1 + 履行状态二分类 F1 |
| 平台责任 | 4 类 F1（计分）；「不担责 vs 其余」二分类仅作诊断 |
| 处置措施 | 措施集合多标签 F1 |
| 处置优先级 | **覆盖加权 Kendall τ**（共现 <2 计 0；漏项按覆盖折减） |
| 门限项 数据溯源率 | 结论覆盖率 × 引用有效率（micro-F1），作为乘性因子 `max(0.6, min(1, 率/0.6))` 折减总分（**保底 0.6**，不归零） |

### 三个必须知道的取舍

1. **`element_judgments` 只需对 gold 出现的要素键负责**，多输出的键不计分，可放心全量输出；
2. **边界结论为「不构成侵权 / 存疑待查」时，task_C 两项措施字段真值均为空列表**，
   预测也应给空列表（**正确判空计分**，不是缺失）；
3. **`citations` 是本样本逐条相关的引用**，把 `labels.json` 的法条表整体铺满
   会因精确率崩塌而**拉低**门限项——引用有效率是逐样本 micro-F1。

### 读分提醒

以下**不是缺陷**，而是指标设计特性，单独看某一项会误读，必须联合判读：

- **二分类 / 子集类指标存在「多数类基线效应」**：完全空白的提交在
  「边界子集类型完全一致率 / 组织化侵权识别一致率 / 平台义务履行状态 F1」三项上
  仍可得 0.92 / 0.94 / 0.26。这三项必须与 **侵权类型 Macro-F1**、
  **平台责任承担 F1** 联合判读。
- **门限项「数据溯源率」的可达性**：阈值 **0.6** 是**折减项而非淘汰项**
  （低于阈值时总分按 `溯源率/0.6` 折减，**最低 0.6**，不归零）。官方参考解在初赛实测 0.5191、在验证集实测 0.5541，均未过线；
  把「类型认定」做扎实、并把引用逐样本对齐，就能过线。
